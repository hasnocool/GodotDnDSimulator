# v0.7 Godot Vertical Slice

v0.7 turns the merged v0.4 actor, v0.5 combat, v0.6 spatial, and C1-C3 Godot-client foundations into one small playable tactical battle without moving rules authority into Godot.

## Goal

The vertical slice proves this production path end to end:

```text
Godot semantic input / HUD intent
        ↓
ClientInteractionController
        ↓
read-only engine query / preview
        ↓
engine-approved command intent
        ↓
EngineBridge
        ↓
TacticalVerticalSliceSession
        ↓
CombatRuntime + SpatialRuntime
        ↓
resolved authoritative snapshot
        + presentation events
        ↓
AuthoritativeMirror
        ↓
Godot map / actors / HUD / animation / diagnostics
```

The client can display, select, preview, animate, and submit intent. It cannot decide movement legality, path cost, attack legality, damage, LOS, cover, AoE membership, action economy, turn ownership, or random outcomes.

## Authoritative demo encounter

The local bridge exposes an original two-actor encounter named **Sunken Courtyard**.

The encounter is intentionally small and uses project-owned placeholder names and primitive visuals. It exists to prove architecture rather than provide final campaign content.

### Actors

- `actor:ember` — Ember Scout;
- `actor:shale` — Shale Warden.

Both actors use the merged shared `ActorState`, `CombatRuntime`, and v0.6 spatial placement model. No Godot-side combatant model is authoritative.

### Map

The logical map is an 8×6 bounded square space with 5-foot logical cells. It includes representative spatial cases:

- open floor;
- difficult shallow-water cells;
- raised stone cells with elevation;
- blocking pillars that provide cover;
- a blocking wall that also blocks LOS.

Godot renders those logical facts using simple 3D primitive meshes. The scene does not infer terrain mechanics from mesh geometry.

## Composite tactical session

`engine/src/godot_dnd_engine/vertical_slice.py` owns the client-facing composite tactical session for this milestone.

It does not replace the lower-level runtimes. It composes them:

- v0.4 `ActorState` remains actor authority;
- v0.5 `CombatRuntime` owns encounter status, initiative, turns, action economy, attacks, damage, HP, and life state;
- v0.6 `SpatialRuntime` / `SpatialQueryService` own occupancy, pathing, cost, reach, LOS, cover, areas, and movement-mode legality.

The composite session gives the client one coherent tactical snapshot and one optimistic sequence for tactical commands. Internal combat/spatial event sequences remain owned by their respective subsystems.

## Bridge capabilities

When the v0.7 provider is enabled, bridge negotiation adds:

- `tactical.vertical-slice.v1`;
- `tactical.commands.v1`;
- `tactical.queries.v1`;
- `spatial.queries.v1`;
- `spatial.previews.v1`.

Core-only bridge mode remains available with:

```bash
godot-dnd-client-bridge --core-only
```

That compatibility mode preserves the generic C1-C3 bridge/shell behavior and uses the original tactical stub.

## Initial synchronization

When `tactical.vertical-slice.v1` is negotiated, `AppShell` requests:

```text
tactical.snapshot
```

instead of `bridge.snapshot`, then loads:

```text
res://scenes/tactical/tactical_vertical_slice.tscn
```

Without the tactical capability, the shell continues to request `bridge.snapshot` and load the C2 reconstruction stub.

## Tactical snapshot

The composite snapshot uses the existing v1 snapshot envelope and includes a `tactical` state block containing:

- encounter ID/status;
- round and turn index;
- current actor ID;
- initiative rows;
- actor IDs, names, teams, HP, AC, life state, conditions, movement modes, and current action economy;
- authoritative logical positions/elevation;
- logical map dimensions/cell size;
- non-default terrain metadata;
- recent resolved presentation events.

Godot's `AuthoritativeMirror` stores this snapshot exactly as authoritative state. Presentation scenes consume deep copies.

## Read-only tactical queries

### `tactical.actions`

Returns coarse engine-side availability for the selected actor's Move, Strike, and End Turn actions.

This enables/disables HUD controls but does not replace destination/target validation.

### `tactical.attack_preview`

Returns authoritative targeting diagnostics including:

- legal/illegal;
- reason;
- distance;
- reach;
- LOS;
- cover classification/sources.

`tactical.attack` is also available through the preview channel so C3 cancellation/generation handling applies to target hover changes.

## Spatial previews

The v0.7 session delegates `spatial.*` queries/previews directly to v0.6 `SpatialQueryService`.

The client uses:

- `spatial.reachable` for reachable-cell overlays;
- `spatial.path` for hovered path/cost previews;
- `spatial.area` for generic area/debug visualization;
- v0.6 distance/LOS/cover through the tactical attack preview.

A missing path/reachable budget is filled from the active combatant's v0.5 movement budget before the query is executed.

## Typed commands

### `tactical.move`

Payload:

```json
{
  "destination": {"x": 2, "y": 2},
  "movement_mode": "walk"
}
```

Resolution:

1. validate campaign/session/current actor/expected tactical sequence;
2. v0.6 validates the complete route and authoritative cost;
3. v0.5 spends exactly that cost from current movement;
4. new spatial/combat states are retained;
5. a fresh composite tactical snapshot is returned.

### `tactical.attack`

Payload:

```json
{"target_id": "actor:shale"}
```

Before resolution, the session verifies through existing runtimes that the encounter/turn/action state is valid and that v0.6 reports the target within the demo strike's reach and visible.

`CombatRuntime.perform_attack()` then owns D20 resolution, hit determination, deterministic damage, defenses, HP/life-state changes, and RNG continuation.

Cover is surfaced by v0.6 as targeting/debug information. This vertical slice does not invent a new cover-to-AC rule outside the existing combat/rules runtime.

### `tactical.end_turn`

Delegates directly to v0.5 `CombatRuntime.end_turn()` and returns the resulting authoritative current actor/round state.

## Command reconciliation

Accepted tactical commands return:

```text
snapshot
presentation_events
result
```

`EngineBridge` ingests the snapshot before emitting `command_accepted`, so `AuthoritativeMirror` advances before presentation effects are dispatched.

`presentation_events` are deliberately separate from the authoritative event stream. They describe already-resolved facts such as:

- actor moved;
- attack resolved;
- turn started;
- encounter ended.

`ClientStateCoordinator` forwards them to presentation code without treating them as an alternate reducer or gameplay authority.

## Godot scene architecture

```text
TacticalVerticalSlice
├── WorldEnvironment
├── DirectionalLight3D
├── TacticalMapView
├── Actors
├── TacticalOverlay
├── TacticalCameraController
├── TacticalEventPresenter
├── TacticalOcclusionController
└── CanvasLayer
    └── TacticalHUD
```

### Camera

`TacticalCameraController` provides:

- orthographic isometric projection;
- continuous semantic-action pan;
- middle-pointer drag pan;
- bounded orthographic zoom;
- integer quarter-turn rotation state;
- selected/current actor focus;
- authoritative-map camera bounds;
- reduced-motion snap behavior.

Visual easing never changes the logical quarter-turn or authoritative state.

### Map

`TacticalMapView` converts logical cells to presentation coordinates and adds stable grid metadata to pickable surfaces.

Its responsibilities are visual only:

- floor/terrain primitive meshes;
- elevation display;
- obstacle placeholders;
- logical-cell ↔ world coordinate presentation mapping;
- camera bounds.

### Actor registry

`TacticalActorView` instances are keyed by authoritative actor ID. Each view provides:

- placeholder 3D mesh;
- pick collider with stable actor metadata;
- selected/hover/current-turn indicators;
- name and HP/AC labels;
- presentation-only movement tween;
- reduced-motion snap behavior.

No scene node stores canonical HP, position legality, or combat resolution.

### Picking and interaction modes

Pointer raycasts resolve either:

- `actor_id`; or
- logical `grid_x` / `grid_y` metadata.

Those stable IDs/cells feed the existing C3 `ClientInteractionController` modes:

- inspect/select;
- move;
- target;
- shape preview.

Move and target previews remain cancellable. Confirmed commands retain C3 duplicate-submit and post-submit cancellation protections.

### HUD/action bar

The tactical HUD displays:

- round/current actor;
- initiative order;
- selected actor HP/AC/movement;
- engine preview diagnostics;
- combat log;
- Move / Strike / End Turn controls;
- an area-debug control.

Action availability comes from `tactical.actions` plus authoritative snapshots; the HUD does not hardcode legality.

### Debug overlays

`TacticalOverlay` renders engine-returned:

- reachable cells;
- path cells and cost context;
- generic area cells;
- target line colored from the authoritative attack-preview result.

LOS/cover/distance details are also displayed in the HUD preview status.

### Event presentation

`TacticalEventPresenter` maps resolved presentation events to:

- combat-log lines;
- actor emphasis hooks;
- audio cue IDs.

Authoritative snapshot progression never waits for presentation completion.

### Foreground occlusion

`TacticalOcclusionController` fades visual nodes in the `tactical_occluder` group when they lie in the camera-to-focus presentation corridor.

This is purely a visibility aid. It does not affect v0.6 LOS or cover.

## Input flow

Default C3 bindings remain remappable. Important defaults include:

- WASD / arrows — pan;
- mouse wheel / configured controller controls — zoom;
- Q/E / shoulder buttons — quarter rotation;
- F / controller Y — focus;
- left click / controller A — Select intent;
- Enter/Space / controller A — Confirm;
- Escape/right click / controller B — Cancel.

HUD buttons call the same interaction/controller command path rather than mutating tactical state.

## Playing the slice

1. start the local bridge normally;
2. launch the Godot client;
3. select the current actor;
4. choose Move and inspect authoritative reachable/path previews;
5. confirm a legal destination;
6. choose Strike and target the opposing actor when engine reach/LOS permits;
7. end the turn;
8. control the next actor;
9. continue until the encounter ends.

The two sides are both player-controllable in v0.7. Autonomous opponent AI is a later concern and is intentionally not introduced here.
