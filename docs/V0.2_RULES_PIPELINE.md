# v0.2 Official SRD Pipeline

## Status

This document describes the implemented v0.2 ingestion infrastructure. The milestone is **not complete** until the pinned official SRD 5.2.1 PDF has been fetched and the complete 364-page source has been extracted, compiled, schema-validated, audited, and reproduced deterministically.

`TODO.md` is the authoritative completion checklist.

## Purpose

The importer turns an explicitly approved licensed source into canonical, provenance-rich rule data without making runtime gameplay depend on PDF parsing, HTTP, or free-form source-document interpretation.

```text
approved source policy
        ↓
async fetch / verified cache
        ↓
source manifest + SHA-256
        ↓
PDF extraction
        ↓
normalization
        ↓
canonical entity compilation
        ↓
kind-specific JSON Schema validation
        ↓
canonical JSONL + reports + attribution
```

The authoritative game engine remains under `engine/`. Everything under `tools/rules_importer/` is development-time tooling.

## Approved production source

The machine-readable allowlist is `config/rules/sources.json`.

The initial production source is:

- source ID: `wotc-srd-5.2.1-en`;
- work: System Reference Document 5.2.1, English;
- publisher: Wizards of the Coast LLC;
- landing page: `https://www.dndbeyond.com/srd`;
- media type: PDF;
- license: CC BY 4.0;
- raw source policy: transient local cache only;
- expected SHA-256: pinned in the source policy.

The importer rejects unknown source IDs and fails closed when the source policy, host, media type, or pinned checksum does not match.

Do not add a new source by copying an existing policy and changing the URL. Follow `docs/RULES_INGESTION.md` and review the work, publisher, license, redistribution rights, attribution, and branding/trademark boundary first.

## Installation

The runtime engine intentionally has no PDF/HTTP dependency. Install importer dependencies explicitly:

```bash
python -m pip install -e '.[rules]'
```

For development/test tooling:

```bash
python -m pip install -e '.[dev]'
```

Python 3.12+ is required by the project.

## Fetch

```bash
python -m tools.rules_importer.cli fetch
```

Default cache location:

```text
.cache/rules/wotc-srd-5.2.1-en/
├── source.pdf
└── source-manifest.json
```

`.cache/` is ignored by Git.

The fetcher:

- uses `httpx.AsyncClient`;
- follows redirects but requires the final source to remain HTTPS on the approved D&D Beyond media host;
- applies a bounded source-size limit;
- records ETag and Last-Modified when supplied;
- uses HTTP validators for repeat requests;
- records retrieval time, source/license/version identity, importer version, final URL, size, media type, and SHA-256;
- compares downloaded bytes to the pinned expected SHA-256;
- re-hashes cached bytes before trusting a cached manifest;
- performs disk work outside the async event-loop thread.

A checksum change is a review event, not an automatic update. Update the allowlist only after verifying an official upstream release/erratum and reviewing the resulting canonical diff.

## Build

```bash
python -m tools.rules_importer.cli build
```

Default generated output:

```text
content/generated/srd-5.2.1/
├── entities.jsonl
├── import-report.json
├── unsupported-mechanics.json
└── ATTRIBUTION.txt
```

Before extraction, the pipeline verifies the artifact identity against the current source policy and re-hashes the source file again. This prevents a caller from bypassing the approved fetch path with an artifact that merely claims the expected source ID.

## Extraction

`pypdf` converts the PDF into a typed intermediate stream of:

- headings;
- paragraphs;
- list items;
- table rows.

The extractor preserves:

- page number;
- source order;
- bookmark/outline title where available;
- heading level where available;
- table cell structure where detected.

PDF parsing is dispatched with `asyncio.to_thread` so it does not block the async event loop.

The current extractor intentionally favors deterministic conservative classification. The full official-source audit may reveal headings/tables requiring improved structural parsing; those should become extractor rules and regression fixtures rather than manual edits to generated data.

## Normalization

Normalization currently performs deterministic, semantics-preserving transformations such as:

- Unicode NFKC normalization;
- non-breaking/duplicate whitespace normalization;
- canonical dice notation such as `1 d 20 + 5` → `1d20+5`;
- normalized table-cell whitespace.

Ambiguous prose is not silently rewritten.

## Canonical entities

The v0.2 compiler creates deterministic **data-only** entities. It does not pretend prose has already become executable D&D behavior.

Each entity records:

- stable entity ID;
- kind;
- canonical name;
- schema version;
- executable-support status;
- licensed source text for the represented section;
- source ID/version/license/hash;
- source page range;
- source section;
- structured mechanics placeholder.

Stable IDs include kind, section slug, and heading slug. A duplicate stable ID fails compilation instead of being silently numbered according to document order.

Executable mechanics are intentionally deferred to the v0.3 rules runtime/effect pipeline, where they can be represented with typed triggers, requirements, targets, rolls, modifiers, resources, effects, durations, and reactions.

## Schemas

Versioned rule schemas live under `schemas/rules/v1/`.

The common entity envelope validates provenance and common fields; kind-specific schemas cover:

- rules;
- actions/reactions;
- abilities/skills/saves;
- conditions/effects/modifiers/resources;
- classes/species/backgrounds/features/feats as character options;
- spells;
- items/weapons/armor/equipment;
- creatures/monsters;
- movement/vision/senses/terrain primitives.

Schemas are executed through JSON Schema Draft 2020-12 validation, not merely syntax-checked.

## Deterministic output

Canonical entities are sorted by stable ID and serialized with stable key ordering.

`import-report.json` records:

- source ID;
- source SHA-256;
- importer version;
- total entity count;
- counts by kind;
- counts by implementation status;
- unsupported primitive counts;
- canonical output SHA-256.

The deterministic fixture smoke test performs two independent builds and compares every generated output byte:

```bash
python -m tools.rules_importer.smoke
```

## Diffing upstream versions

`diff_entities()` compares canonical datasets by stable ID and reports:

- added;
- removed;
- changed;
- unchanged;
- prose-only changes;
- mechanical representation changes.

The intended errata/update workflow is:

1. verify the new official source and license;
2. update/add its source policy;
3. fetch and pin the reviewed bytes;
4. build the new canonical dataset;
5. diff against the current supported source version;
6. inspect ID changes, mechanical changes, unsupported primitives, and migrations;
7. update runtime primitives/tests as required;
8. update attribution, changelog, TODO, and compatibility documentation.

## Attribution

The repository contains `LICENSES/SRD-5.2.1-ATTRIBUTION.txt`, and generated builds emit an independent `ATTRIBUTION.txt` so licensed-source attribution cannot be lost when original-game credits are edited.

Do not weaken or remove attribution generation as part of unrelated content or UI changes.

## Testing

Importer tests cover:

- approved/denied source policies;
- bad host/license/media/checksum policy inputs;
- mocked HTTP fetch and cache reuse;
- upstream checksum changes;
- final redirect restrictions;
- cached-manifest mismatches;
- PDF extraction and malformed PDF rejection;
- outline/bookmark handling;
- normalization;
- deterministic compilation;
- stable-ID collisions;
- schema validation failures;
- provenance/report consistency;
- artifact identity mismatches;
- source-file tampering after manifest creation;
- canonical diff classification;
- CLI dispatch;
- byte-for-byte deterministic fixture builds.

Normal local validation:

```bash
ruff check .
mypy engine/src tools/rules_importer
pytest --cov=godot_dnd_engine --cov=tools.rules_importer --cov-report=term-missing
python -m tools.rules_importer.smoke
```
